Minikube now, EKS later

Probes are how the kubelet decides whether a pod is alive and ready.

In your local cluster, the kubelet on the Minikube node calls endpoints on your FastAPI container. It reports status back to the API server, and Services route only to ready pods.

Liveness

If this fails repeatedly, kubelet restarts the container.

Readiness

If this fails, the pod stays running but receives no Service traffic.

Startup

Gives slow model boot a grace window before liveness takes over.

Minimal YAML For Your API

Keep `/health` for liveness. Add `/ready` when the app needs to distinguish alive from ready. 

readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 3
  periodSeconds: 5

livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 10
  periodSeconds: 10

FastAPI Endpoints

Kubernetes treats HTTP 200-399 as probe success. Return 503 when the pod is alive but not ready. 

model_loaded = True

@app.get("/health")
async def health_check():
    return {"status": "ok"}

@app.get("/ready")
async def ready_check():
    if not model_loaded:
        raise HTTPException(
            status_code=503,
            detail="model not loaded",
        )
    return {"status": "ready"}

Debugging Commands

  • kubectl get pods shows whether the pod is Ready.
  • kubectl describe pod <pod> shows probe failures and restart events.
  • kubectl get endpoints hello-world shows which pod IPs the Service can route to.
  • kubectl logs deployment/hello-world shows FastAPI probe requests and app errors.

For The Mock API

`/ready` can return ready immediately. The point is learning how the kubelet and Service react to endpoint status.

For The Real Model

`/ready` should fail until weights are loaded, GPU memory is allocated, and warmup inference has completed. That keeps traffic away from cold pods.
